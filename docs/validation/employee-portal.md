# Employee Web Portal and Account Authorization

## Sign-In and Joining

Open the knowledge base root address (`http://127.0.0.1:8765/` on this machine) and sign in with an email address and password. The first developer must change the initial password on first sign-in. Everyone else joins only through invitation links registered and generated by an administrator; the page auto-fills the email address as read-only and requires the initial password to be entered twice. By default, a link is valid for seven days and single-use; resending invalidates the previous link. If a password is forgotten, an administrator with the required permission generates a password reset link.

Web sign-in sessions are stored in an HttpOnly cookie; passwords or session credentials are never written to localStorage; over HTTPS, the cookie is set with the Secure flag. Signing out clears the current session; a password change, account deactivation, or role adjustment revokes the account's existing sessions and AI authorizations. Legacy access-code management and shared-code authentication are disabled.

## Three-Tier Permissions

Developers can invite and manage developers, administrators, and regular users, and manage all business divisions. Administrators can invite and manage the administrators and regular users whom they themselves registered and who still fall within their business division's management scope; they cannot invite developers, and they review documents for their own department. Regular users can submit and retrieve materials they have permission to access and have no invitation privileges. The server checks permissions on every request; front-end choices cannot be relied on for privilege escalation, and the last active developer cannot be deactivated or demoted.

In "Account Management", enter the other person's email address and choose a role and business division; after the link is generated, copy it and share it yourself; the project does not send email automatically. The default share address comes from the protected runtime configuration `AGICO_KB_PUBLIC_URL`; you may also explicitly enter a knowledge base address that colleagues can access. A local-machine address cannot be used from other computers.

## Upload, Review, and Preview

You can select individual files, an entire folder, or drag in a folder together with all levels of its subfolders. All files within it are included by default; the business division the batch belongs to is selected explicitly and is not guessed from the content. Uploads enter a pending-review workflow; files that finish parsing are listed first and are published after review by the person in charge. Regular users see their own submissions, administrators see their own department, and developers can manage all departments.

For images, PDFs, and Office documents, clicking the thumbnail or file name opens a read-only full-text preview that supports scrolling, page-number jumps, rotation, and zooming, with a default of 75%. For CAD and similar formats, image previews are used to locate the original files. All originals, thumbnails, and preview pages re-check current permissions; previously loaded caches do not bypass revocation or deactivation.

## Connecting an AI Assistant

After signing in, click "Connect AI Assistant" and choose Codex, Accio, or a generic AI assistant. The configuration snippet contains only the MCP address, with no employee passwords, shared access codes, or static Authorization headers. Clients that support OAuth open the knowledge base web sign-in, the account owner confirms the authorization, and then initialize, the tool list, and kb_catalog are verified; clients without OAuth support cannot bypass authentication. The business division must still be specified explicitly before uploading.

The web page provides configuration instructions and must not claim that the client is already connected. Service reachability, OAuth completion, and actual tool calls by the current agent are verified separately. Existing clients must remove the old static Authorization request header for the same-named service and re-authorize; for Codex, run `codex mcp login agico-kb`.

The [account and invitation design](../design/account-login-and-invitations.md) describes the current account behavior. The legacy access-code test report is evidence of the old mode and cannot be used as connection instructions for the account mode.
