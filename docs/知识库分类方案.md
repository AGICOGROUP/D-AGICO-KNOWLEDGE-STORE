范围：统一知识库的组织分区、资料分类和检索规则。后续调整在本文件中整合覆盖，避免追加矛盾结论。

## 1. 设计结论

采用“组织分区 → 资料用途”的两级浏览结构，结合产品、型号、项目和文件格式等筛选项。默认不再增加固定目录层级。

两类需求共用这套组织方式：Codex、Accio 等 Agent 通过 MCP 按需了解公司的背景、事实、规范和经验，让各种回答和任务结果更贴合公司需求；员工通过已有网页／钉钉入口委托 Agent 上传、查找和获取文件。分类服务于通用企业知识扩展，具体业务例子不决定系统主流程。

这是同一套后台中的逻辑分区，不要求每个部门部署独立系统、数据库或向量服务，也不要求员工维护索引目录。原文件、数据库记录和内容索引使用一致的文件标识、组织归属和版本关联。

## 3. 二级资料分类

所有组织采用同一套简单分类，按需使用；空分类不必在日常浏览中展示。分类描述用于入库和查找，不预设各事业部拥有相同业务。

| 分类 | 适用内容 |
|---|---|
| 组织与业务背景 | 部门职责、业务范围、产品线概览、业务术语、必要的公司介绍 |
| 产品与技术资料 | 产品说明书、参数表、技术标准、图纸、CAD、3D 模型包、BOM、安装和维护资料 |
| 项目与客户资料 | 项目需求、项目方案、客户往来资料、历史报价、合同和项目交付文件；按实际权限管理 |
| 流程规范与模板 | 业务流程、工作要求、操作规范、报告模板、报价模板及其他可复用工作模板 |
| 经验案例与常见问题 | 项目复盘、故障处理、经验总结、常见问答和典型案例；保留来源及适用条件 |
| 其他资料 | 暂不适合以上分类的文件，先收纳，后续按实际需要调整 |

选择主要用途作为一个主分类即可。具体产品说明书归“产品与技术资料”；用于反复填写的报价模板归“流程规范与模板”；某个项目实际形成的报价归“项目与客户资料”。同一文件不因多种用途重复保存，可通过关联信息被不同任务找到。

“待确认”“处理中”“已发布”等是状态，不作为二级资料分类，也不另建同名业务目录。

## 4. 格式、产品和项目用筛选项表达

不在每个部门下固定建立 PDF、Word、Excel、PPT、CAD 等格式文件夹。同一产品的说明书、参数表和图纸应能一起找到；格式由系统自动识别并提供筛选。

首版保留以下基本信息：

- 系统记录：文件标识、文件名、格式、大小、上传者、时间、存储位置、处理状态、版本及发布状态。
- 组织与用途：主要归属组织、一个主分类、实际访问范围。
- 按需填写：产品／型号、项目／客户标识、文档／图纸／零件编号、业务日期、相关文件。业务日期取资料本身的报价／项目等日期，不以上传时间代替。

没有产品或项目的资料不强制填写这些字段。不要求员工上传时完成一长串标签；可从所选分区和当前任务带入信息，由 Agent 提议补充，负责人在发布时检查必要信息。

产品、型号和项目等字段承担跨格式关联与精准过滤；向量检索用于补充语义查找，不用来决定权限、正式版本或组织归属。

## 5. 上传与归类

1. 先保存原文件及提交记录；上传入口指定的分区作为归属候选，并由后台校验提交权限。
2. 如用户未指定，可采用可信登录身份对应的部门作为初始归属候选，不据此自动发布或扩大访问权限。
3. 后台自动识别文件格式，完成支持的解析、关键词索引和向量索引；Agent 可按现有能力提出资料类别、产品和项目关联建议，不增加专门分类 Agent。
4. 归属不明确时保留待确认提交，沿用受控的提交可见范围；不得为了便于分类直接放入公司公共知识或分享给其他部门。主分类不明确可暂用“其他资料”。
5. 发布前由授权负责人确认归属、必要的关联信息、版本与可见范围。处理完成不等于自动发布。

文件归类不会阻塞原文件保存。无法解析的 CAD、模型包或异常文件仍可登记、按基本信息搜索和获取；处理失败可以重试，并明确标注当前内容读取能力。

## 6. 跨部门资料与权限

- 一份资料保留一个主要归属和一套版本，由对应负责人维护。
- 多部门使用时，对原记录设置适当的共享范围或关联引用，不按部门复制多份。
- 经确认属于公司通用资料的，可归到“公司公共知识”；特定部门的正式产品资料即使跨部门共享，也可以继续由原部门负责。
- 部门分区用于组织与检索；实际访问权限由后台强制执行，不能仅靠文件夹名称或 Agent 自述身份控制。
- 未选部门不表示可以访问全部资料；搜索结果、摘要、原文、附件都只返回调用者有权获取的内容。
- 同一分区可以存在限制范围更小的资料，不因员工属于该部门就自动取得所有文件权限。具体范围沿用统一后台权限能力，首版不另建复杂审批系统。

## 7. Agent 检索与读取

优先使用任务中明确的文件、组织、产品、型号或项目条件。用户明确指定的范围为硬条件；员工所属部门只能作为查询相关性线索，不能无依据排除其有权查看的跨部门资料。

- 问答和任务中调用：根据需要查背景、核对事实、应用规范与模板、参考经验，交回原 Agent 理解并用于当前工作；不依赖员工每次明确要求搜索。
- 查公司或部门背景：只有任务需要时才读取相关的少量正式背景条目，不加载全库目录或要求每次任务先读背景。
- 找文件：在权限范围内，按归属、名称、型号、资料类型和适用正式版本定位，返回文件卡片与获取引用。
- 问内容：采用关键词与向量混合检索，返回相关原文片段、文件版本和位置，需要时展开章节或表格。
- 已指定文件：直接在该文件的目标版本内查找，避免再次搜索全库。
- 多个部门有相似产品且任务不明确：返回少量能区分的候选，必要时由 Agent 请员工选择，避免猜测。
- 已有明确来源且支持直接读取：允许按文件与位置直接获取，减少重复搜索。

不同项目或时期的业务资料是独立记录，按主要用途归类并通过产品／项目等信息关联。已确认的历史记录继续参与普通授权检索；同一记录内部的修订才使用正式版本筛选。资料年代较早不等于该资料是被替换的旧版本。举例而言，历史报价归“项目与客户资料”，这是通用规则的一种应用，不需增加专用报价分类体系。

相关公共知识可在有权限且与任务相关时一起检索。默认返回适量结果和继续读取入口，不把所有分类、文件列表或完整文件交给模型；暂不设严格固定的任务 token 配额。

这些是同一后台与 MCP 的查询方式，不增加独立的检索决策 Agent 或多层记忆服务。

## 8. 示例

以下仅示意分类方式，不表示已获知百斯特事业部的实际产品或已有文件。

```text
百斯特事业部
└─ 产品与技术资料
   ├─ A产品说明书.pdf
   ├─ A产品参数表.xlsx
   └─ A产品图纸.dwg
```

三份文件通过相同的产品／型号信息关联，各自保留版本和发布状态。员工可查“这个产品的全部正式资料”，也可筛选“图纸”；Agent 可搜索说明书中的安装要求。源图纸与其预览 PDF 应关联具体版本，不能仅按文件名推定为同一版本。

CAD／3D 的外部依赖按完整包保存，不为分类而拆散模型依赖文件。

## 9. 首版落地边界

- 采用 8 个初始组织分区和 6 个通用资料分类；作为可调整配置，不写死在接口中。
- 默认两级浏览，产品、项目和格式使用筛选项；后续实际有需求再增加展示分组。
- 不在本次创建空的业务文件目录树，不导入或搬移现有公司资料，不配置真实用户权限。
- 开发时把组织归属、分类和产品等过滤能力接入统一后台与 MCP，网页／钉钉沿用现有 Agent 链路。
- 本方案不改变“自由提交、授权发布”、版本冲突检查、可恢复撤下和独立备份的总体规则。
- 初期只验证归类、按部门查找、跨部门授权访问、精准定位和按需内容读取是否有效，再根据真实使用优化。
