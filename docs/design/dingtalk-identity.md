# 钉钉身份接入与虚拟机验收设计

日期：2026-10-19。状态：设计已确认，代码与隔离测试已实现；虚拟机独立实例已启动，钉钉 PC 真实免登已由用户及后端绑定/会话共同验证；手机与正式切换待验收。

## 目标与边界

知识库仍为公司服务器运行的网页应用，员工在钉钉工作台的内置页面使用。钉钉提供企业员工身份、组织架构和部门归属，取代员工逐人登记、邀请和单独设置知识库密码的流程。知识库保留资料审批、事业部访问和 AI 助手授权能力。

复用现有 PostgreSQL、principals、memberships、账号会话和 MCP OAuth；不重建文件库、不修改原件或解析结果。当前正式账号 ID、密码哈希、角色、创建关系及审计均保留。先在独立虚拟机实例验收，不切换本机正式实例的登录方式。

## 选择的实现方式

采用企业内部 H5 网页应用免登。钉钉中的前端通过官方 JSAPI 取得临时免登码，后端使用该应用凭证向钉钉验证并获取员工详情，再建立现有 HttpOnly 会话。应用密钥只保存在服务器受保护配置中，不发给前端、不进入 Git、普通日志或测试报告。

不另建人员目录服务、不复制公司的人事管理功能，也不把 CLI 登录凭证当作服务器长期运行的应用凭证。CLI 用于开发配置，运行时使用企业应用自己的凭证。

## 身份与会话

1. 身份唯一键为企业 CorpId 加员工 userId；unionId 仅作辅助。后端使用固定已配置企业和应用凭证验证身份，拒绝由客户端直接指定员工、角色或部门。
2. 免登提交使用同源校验、短期一次性随机挑战、服务器侧限流。错误消息不包含免登码、密钥或完整钉钉响应。会话沿用 Secure/HttpOnly/SameSite cookie 和 CSRF 检查。
3. 新员工在应用授权范围内首次登录时创建关联账号。员工未提供邮箱时仍可按钉钉身份登录；展示名称与身份键分离，不伪造真实公司邮箱。
4. 已有邮箱账号通过双重身份验证绑定：先验证既有知识库账号，再验证钉钉身份，或由开发人员核对后明确指定绑定。不能根据同名、邮箱相似、首次请求就接管已有账号。
5. 绑定后保留既有 principal_id 及关联记录。禁止自动将普通员工绑定到已有最高权限账号，也不能因钉钉管理员身份自动提升知识库角色。
6. 钉钉模式启用后，员工的邮箱密码登录、邀请激活和密码重置入口关闭；后端同样拒绝这些旧路径，避免绕过钉钉离职状态。仅保留配置中明确指定且仍有效的最高权限本地账号，作为受控运维入口。
7. 本阶段以钉钉内使用为主；普通浏览器不显示员工密码登录。AI OAuth 仍沿用既有授权流程，必要时引导在钉钉中打开授权页。端外钉钉扫码登录作为独立可选能力，未实现不得标为已支持。

## 部门、角色与资料权限

1. 用稳定钉钉部门 ID 映射已有知识库事业部 ID。映射配置明确包含哪些下级部门，先读取真实结构再设置，不按部门名称猜测。
2. 多部门任职按明确映射取并集。未映射部门不自动获得业务事业部权限；处于应用授权范围内的员工保留通用国际集团、公共知识库的默认阅读权限。
3. 默认角色为普通用户。开发人员、资料管理员由知识库明确授权；公司钉钉管理员和部门主管不会自动得到知识库最高权限。
4. 已有创建人关系作为历史记录保留。钉钉模式下人员新增、组织归属由钉钉维护，知识库不再要求管理员邀请员工；知识库角色及审批范围仍可由获授权开发人员设置。
5. 管理员仅管理被授权且与其有效部门范围一致的资料。新部门归属不自动赋予审批权；部门移出后旧审批权立即失去对应部门的有效范围。
6. 所有现有业务接口继续依赖统一 Principal，包括列表、搜索、原件下载、预览、缩略图、上传、审核及 MCP。不能只隐藏菜单而保留越权接口。

## 同步与故障行为

1. 首次读取授权范围内的组织结构；后续定期刷新组织结构，对已绑定员工重新核对部门和有效状态。增量事件用于加快更新，定期核对作为兜底，不以事件是唯一正确性来源。
2. 身份有效性最长缓存五分钟。过期时必须重新核实；钉钉暂时不可用时不延长失效缓存，不自动切回员工密码登录。开发运维入口独立保留。
3. 明确离职、停用或失去应用授权时，拒绝新登录并撤销网页会话、MCP OAuth 授权和未使用授权码；保留账号及历史记录。即使没有新的网页登录，已绑定员工的 MCP 访问也必须受同一有效性检查约束。
4. 部门变化后更新业务访问范围，并使已有会话使用新范围；不能只在首次登录时同步。同步失败、分页未结束或权限错误不能解释为全体员工离职并批量停用。
5. 同步结果在现有数据库管理锁下写入，并比较原始证据时间，丢弃其他进程已经更新后的旧响应；远程网络调用设置有限超时，不在持有长事务锁期间等待钉钉。部门树缓存的证据时间同时约束员工缓存，不能叠加延长五分钟有效期。

## 钉钉权限与配置

只申请实际用于此方案的企业只读权限：

- qyapi_get_member：成员信息读权限。
- qyapi_get_department_list：通讯录部门信息读权限。
- qyapi_get_department_member：通讯录部门成员读权限。
- qyapi_get_microapp_list：企业已安装的应用列表只读权限。用员工可用应用列表核对实际 AgentId，不以“仍在通讯录”代替应用可用性检查；不申请微应用管理权限。

不申请通讯录管理、写入、考勤、审批或消息发送权限。应用可见范围先限于开发人员及明确选定的试用人员；涉及扩大范围和发布时展示准确配置后再执行。

服务器配置包括：钉钉启用开关、CorpId、应用 ID、受保护凭证文件路径、部门映射、受控运维账号集合、PUBLIC_URL、允许访问主机、登录/可信域名配置。业务代码不硬编码虚拟机 IP、临时域名或正式服务器域名。

测试入口必须为钉钉客户端能够访问的地址。虚拟机私网 IP 仅适用于同网访问；远程手机验证需可访问的测试 HTTPS 入口。临时入口发布与暴露数据必须限定测试实例和访问范围，不能代替正式固定域名。

## 验收顺序与通过标准

1. 新建隔离数据库 schema 和合成账号，验证真实协议结构的模拟成功/拒绝、无密码会话、重放、超时、错误企业、异常响应、限流和 CSRF。模拟通过不等于真实钉钉接通。
2. 验证同名/同邮箱不能接管原账号、绑定保留原 ID、停用账号不可复活、管理员不提升为开发人员、未映射/多部门/调部门权限和公共资料默认读取。
3. 验证旧员工密码路径不可绕过钉钉、缓存过期拒绝失效身份、离职撤销网页与 MCP、备份恢复仍保留绑定和历史权限。
4. 启动并核实虚拟机服务，使用单独运行目录和数据库。部署前备份虚拟机原状态与现有正式账号，不覆盖主机正式运行数据。
5. 为应用设置测试入口和只读权限，实际钉钉客户端登录，覆盖开发人员、部门管理员、普通员工及拒绝访问场景。真实员工确认和部门映射只在明确授权范围内进行。
6. 在虚拟机验证重启、登录、上传合成资料、解析、预览、检索、审批和 AI 授权的回归；记录成功项、失败项与未验证项，不因健康接口成功宣称全部完成。
7. 通过后把同一版代码、最新数据库备份及受保护配置迁移到正式服务器。替换 PUBLIC_URL/主机范围，并同步调整钉钉端主页、PC 主页、可信域名及实际使用的回调配置，再执行发布和正式域名冒烟测试。不能把切换描述为仅修改一处网址。
