# 身份登录、业务权限与 AI 授权

## 正式账号和部署保护

2026-10-14 起登记的账号均为正式持久化数据。邮箱、原密码哈希、principal_id、角色、事业部授权、启停、邀请、创建关系和审计随最新数据库备份迁移，不清空、不重新初始化。钉钉接入增加身份绑定，不替换已有主键或文件归属；真实账号和凭证不进入源码、Git 或普通日志。

## 两种运行模式

未配置 `AGICO_KB_DINGTALK_CONFIG_FILE` 时，保留既有邮箱密码和分级邀请模式；本机现有实例仍按此方式运行。

指定受保护钉钉配置后，采用企业内部 H5 免登：员工从钉钉工作台进入，临时免登码由后端用本企业应用凭证验证。钉钉提供人员及部门，知识库保留资料管理、审批和 AI 授权。员工不再逐人邀请、设置知识库密码或重置本地密码，服务端也拒绝这些旧入口。普通浏览器显示钉钉入口指引；端外扫码登录尚未实现。

仅受保护配置中明确指定的、现有且有效的开发人员账号保留本地密码运维入口。会话记录认证来源，避免绑定钉钉后遇上游故障就同时失去维护能力。该入口不等于普通员工可以绕过离职校验。

## 已有账号绑定

已有知识库账号和新钉钉身份必须分别完成验证，关联前再次核对原会话仍有效。公司 CorpId 加员工 userId 是唯一键；不按姓名或邮箱自动绑定，不因钉钉管理员身份提升知识库权限。保留原账号的密码哈希、历史记录及 ID。一名员工只绑定一个账号，一个账号只绑定一个企业员工身份。

未绑定的钉钉员工首次进入时创建普通用户，展示钉钉姓名；内部占位标识不是公司邮箱。已在知识库停用的账号不会因同步自动启用。

## 事业部和资料权限

钉钉部门 ID 显式映射知识库事业部，下级部门仅按真实部门树继承。多部门取已确认映射的并集，未映射部门不猜测业务归属。通用国际集团和公共知识库已发布的部门可见资料全员默认可读，不额外授予审批权。

开发人员管理全部事业部和业务权限；管理员审批范围取“知识库明确授予的审批事业部”与“当前钉钉有效部门”的交集，调部门不自动新增审批权。普通员工无账号管理或审批权。资料列表、搜索、上传、原件下载、缩略图、全文预览及 MCP 共用同一有效身份，旧上传者身份和个人共享不能绕过部门变化。

钉钉模式下不再由知识库管理员邀请员工；开发人员在已同步账号上设置业务角色。旧 created_by 和归属树保留为历史关系，不用它覆盖钉钉组织结构。邮箱模式仍保留分级邀请：管理员只管理自己创建且在授权范围内的子账号，开发人员同级并列。

## 持续核验与 AI

身份和组织证据最多缓存五分钟。超时或异常响应不延长权限；明确离职或失去应用可用范围时撤销网页会话、OAuth 授权和未使用授权码，保留业务记录。网络故障不能批量解释为员工离职。多进程旧响应不得覆盖较新的身份快照。

MCP 继续使用 OAuth 授权码与 PKCE，客户端不接收员工密码或企业应用密钥。即使员工不再登录网页，MCP 读取和凭证刷新也必须重新核对过期身份。网页、MCP、真实钉钉客户端和部署验收分别记录，协议模拟通过不代表真实免登已通过。

详细接入与迁移规则见 [钉钉身份设计](dingtalk-identity.md) 和 [服务器安装说明](../server-setup.md)。
